# Стенд на Rust

Команды выполняются из каталога `rust/`. Эталон – Node 26.3.1, V8 14.6.202.34-node.20, arm64 macOS, сборка Homebrew. Для сборки нужен Rust edition 2024 и компилятор C++20. Node нужен для сравнений с TypeScript.

## Числа

`node tools/check-math.mjs` собирает проверяющую программу и передаёт ей входы и ожидаемые binary64 непосредственно из Node. Для каждой операции берутся 100 000 значений на рабочих диапазонах, ещё 100 000 на смешанных диапазонах и 712 граничных комбинаций, в том числе числа NaN с разными знаками, типами и полезной нагрузкой. Сравнение – по всем 64 битам, включая знак нуля и биты NaN. Векторы не записываются в репозиторий.

| Операция | Реализация |
| :-- | :-- |
| sin, cos | В установленной libnode экспортированы `v8::base::ieee754::sin/cos`. Флага `--use-libm-trig-functions` у этой сборки нет. Используются ядра fdlibm, включая редукцию больших аргументов по π/2. |
| exp, log, log1p, tanh, atan2 | Функции из того же исходника V8, включая внутренние expm1 и atan, особый случай exp(1) и signaling NaN при выходе логарифма за область определения. |
| hypot | Алгоритм math.tq: максимум модулей, нормирование, умножение на масштаб после sqrt. Для трёх и более аргументов учитывается компенсация потери точности. Бесконечность имеет приоритет над NaN. |
| abs, sqrt, ceil, floor | Операции binary64, как у Float64Abs, Float64Sqrt, Float64Ceil и Float64Floor. Константы PI и SQRT2 имеют ближайшее представимое значение. |
| round, sign, min, max | Ветви ECMAScript: половины округляются к большему, знак нуля сохраняется, Для NaN в min/max воспроизводится порядок обработки аргументов встроенной функцией V8 на arm64. При двух signaling NaN оптимизированный JIT-вызов может выбрать другую полезную нагрузку. В стенде этот случай не возникает. |
| ToInt32, ToUint32, imul | Выделение младших 32 бит усечённой мантиссы и умножение по модулю 2³². hashUnit и hueNoise повторяют math.ts, с беззнаковыми сдвигами. |

Исходники эталона: [ieee754.cc](https://github.com/nodejs/node/blob/v26.3.1/deps/v8/src/base/ieee754.cc), [выбор функций](https://github.com/nodejs/node/blob/v26.3.1/deps/v8/src/codegen/external-reference.cc), [math.tq](https://github.com/nodejs/node/blob/v26.3.1/deps/v8/src/builtins/math.tq). Выбранные ядра собраны статически в jscompat, лицензии лежат рядом с Cargo.toml крейта. Исходные скобки и промежуточные присваивания сохранены. В дизассемблере установленной libnode внутри полинома sin видна серия инструкций fmadd. Например, при −0,6962983277626336 отдельное округление умножения и сложения меняет последний бит. Поэтому только для этих ядер используется режим Clang `-ffp-contract=on` без fast-math. В формулах модели обычные операции Rust округляются отдельно. Другая архитектура или компилятор требуют повторной битовой сверки.

## Текст команд

`node tools/check-print.mjs` сравнивает три формы чисел с Node, а также многострочные таблицы и строки журнала. `number` использует кратчайшую ECMAScript-запись Ryū. Для `to_fixed` двоичная мантисса точно масштабируется степенями 5 и 2 в BigUint, включая округление половин и предел в 100 знаков. Таблица принимает заголовки и упорядоченные строки чисел и текста. Поддержаны формы console.log, используемые стендом, без форматных подстановок. Ширина повторяет ASCII-префикс, удаление VT-последовательностей, нормализацию NFC и ширины символов ICU сборки Node. Диапазоны свойств восстанавливаются командой `node tools/width-data.mjs`.

## Эпизоды версии A

`cargo test -p lab` проверяет четыре SHA-256 цепочек JSON с координатами взгляда, треками и энергией, а также свойства сценариев и политик. Агент получает только сенсорный кадр и управляющие параметры. Оценщик сопоставляет треки с объектами мира после шага.

`node tools/check-traces.mjs` записывает пары файлов NDJSON во временный каталог и проверяет все поля полного снимка, включая начальный кадр. Можно передать путь для сохранения трасс. В имени файла указаны сценарий, политика, зерно и режим. При расхождении печатаются номер кадра, путь к полю и оба значения. Сравнение охватывает все условия bench на зёрнах 1, 2 и 17, включая повтор с 15-го шага, а также эпизод vanish с начальной обучаемой моделью.

## Стенд bench

`cargo run --release -p cli -- bench` последовательно выполняет шесть политик на зёрнах 1–200. Эталон – вывод `node src/lib/lab/bench-cli.ts` из каталога `web/`, без заголовка, который добавляет npm. `node tools/check-bench.mjs` предварительно собирает release, запускает обе команды на этой машине и сравнивает stdout как массивы байтов. При совпадении печатаются размер, SHA-256 и время каждой команды.

## Genesis и сенсомоторная зависимость

Запуск из этого каталога – `cargo run --release -p cli -- <команда> [аргументы]`.

| Команда | Что вычисляет | Аргументы |
| :-- | :-- | :-- |
| `genesis-feasibility` | Проверка контролей движения и существования объекта на проектных зёрнах | Список из `frozen`, `keep-all`, `ideal`, `oracle`. По умолчанию все четыре |
| `genesis-tune` | Подбор шагов обучения на первом порядке | Без аргументов |
| `genesis` | Допуск контролей и парное сравнение площадей на отложенных прогонах | Без аргументов |
| `sensorimotor-feasibility` | Проверка калибровки, совмещения сцены и выбор шага оракула | Список из `frozen`, `ideal`, `oracle`, `neutral`. По умолчанию все четыре |
| `sensorimotor-tune` | Подбор шага калибровки на первом порядке | Без аргументов |
| `sensorimotor` | Проверка неподвижной точки, допуск и сравнение участников | По умолчанию выбранный шаг 0,3. Его можно передать явно как `0.3` или `0,3` |

Например, `cargo run --release -p cli -- genesis-feasibility ideal frozen` выводит результаты двух контролей в запрошенном порядке. Каждое условие выполняется один раз. Метки истинного смещения, существования и коэффициента тела предоставляет драйвер оракула. Остальные обучаемые условия используют сенсорные кадры, команды взгляда и память агента.

### Сверка с TypeScript

- `node tools/check-commands.mjs` предварительно собирает release и запускает семь пар команд – `bench` и шесть команд из таблицы. Эталоном служит прямой вызов каждого скрипта в Node 26.3.1. Проверяются все байты stdout. Для ошибочных аргументов дополнительно сравниваются код выхода и текст исключения. Скрипт печатает размер вывода, SHA-256 и время обеих команд для каждого набора аргументов.
- `node tools/check-training.mjs` записывает две трассы обучения в NDJSON. Проверяются шесть условий на прогонах 61 и 701, начальное состояние и восемь эпизодов учебной программы. Сравниваются каждый выбранный пример движения и пропажи, веса, логиты и все поля оценки на зёрнах 3001–3002. При расхождении указываются прогон, эпизод, поле и оба значения. Необязательный аргумент задаёт каталог для трасс.
- `node tools/check-traces.mjs` также сверяет полные снимки двух эпизодов без тела с идеальными параметрами на зерне 3101 и проверяет исторический SHA-256. При хэшировании чисел и полей Rust используется порядок свойств эталонного JSON.

## Субстрат версии B

Из каталога `rust/` команды запускаются как `cargo run --release -p cli -- substrate-b0`. Полные эксперименты используют несколько процессорных ядер. Один прогон выполняется последовательно. Отчёт собирается в порядке эталона.

| Подкоманда | Эксперимент |
| :-- | :-- |
| `substrate-b0` | Прогноз следующего кадра, контроль без Собеля, копия и необученная решётка |
| `substrate-b1` | Память, частичное закрытие, подсказка оценщика и зонды скрытого положения |
| `substrate-b1b` | Случайные пути, три ширины стены, вес выхода ×50, ложные ожидания и кривые формирования |
| `substrate-b3` | Подвижное окно, постоянный и эпизодический коэффициенты тела, три режима копии команды |
| `substrate-b3b` | Случайные пути, постоянный коэффициент и дополнительная контекстная база |

Размеры задаются в Rust через `Scale`. По умолчанию это решётка 16 × 16, глубина 16, пять прогонов по 2000 эпизодов, 80 шагов на эпизод и 30 шагов обратного распространения. Вложенная `EvaluationSettings` задаёт число оценочных эпизодов, их длину и начала двух непересекающихся диапазонов зёрен. Увеличение разрешения сохраняет физическое поле зрения – 100 × 100 для стационарного сенсора и 50 × 50 для подвижного. На грубой сетке первый кадр выхода может не содержать ни одного центра клетки внутри A. Пустая выборка выхода даёт NaN, остальные метрики рассчитываются по своим выборкам.

`PersistenceSettings` добавляет глубину широкой решётки и число контрольных прогонов B0 и B1. `TrackingSettings` задаёт интервал замеров, число прогонов у широкой стены и удлинённое обучение с весом выхода. `MotionExperiment` выбирает обычные или случайные пути. `cargo test -p substrate eight_by_eight` обучает и оценивает все пять вариантов команд на решётке 8 × 8 с глубиной 4.

### Проверка субстрата

`node tools/check-substrate-traces.mjs` сравнивает с Node каждый канал прогноза на всех 80 шагах и все веса после каждого из трёх эпизодов. Проверяются обычные ячейки, изотропный контроль, память глубины 16 и 28, подсказка, вес выхода и варианты копии команды. При расхождении выводятся эпизод, шаг и индекс. Скрипт также проверяет обе поправки Adam для шагов 1–18 000. Для целочисленной степени используется системная реализация, выбранная сборкой Node флагом `--use-std-math-pow`.

`node tools/check-substrate.mjs` запускает все пять полных сравнений. Для отдельной проверки можно передать имена, например `node tools/check-substrate.mjs b0 b3b`. Каталог эталонов по умолчанию – `coherence-substrate-cache` в системном временном каталоге. Путь можно задать через `SUBSTRATE_REFERENCE_CACHE`. Для каждого вывода сохраняются Git-хэш дерева `web/src/lib`, версия Node, аргументы, исходные байты, их SHA-256 и время выполнения. Сверка требует чистого дерева эталона и проверяет метаданные и контрольную сумму при чтении.

Из stdout перед сравнением исключаются только заключительные строки измерений с числом секунд и одним десятичным знаком. В B0 это «Время от старта до окончания всех обучений» и «Полный запуск с оценкой», в остальных четырёх командах – «Время полного запуска». Хэш и размер относятся ко всем оставшимся байтам, включая переводы строк. Сообщения о ходе отдельных прогонов идут в stderr.

## Нативное окно лаборатории

`cargo run --release -p viewer` открывает «Когерентность» на egui/eframe. Нужен графический сеанс и адаптер, поддерживаемый wgpu. Веб-версия на GitHub Pages остаётся отдельной и не меняется.

Окно повторяет лабораторию версии A: сцену оценщика и вход агента, гипотезы, модель внимания, энергию согласования, сценарии, режимы и вмешательства, а также полный протокол bench. При ширине от 1024 точек сцена и две карточки находятся в соседних колонках; в узком окне разделы идут последовательно. Содержимое прокручивается по вертикали, таблица протокола – отдельно по горизонтали. Субстрата версии B и сборки WebAssembly в окне нет.

Начальное состояние – «Непрерывность», зерно 4, «Полный контур», пуск на 1×. Интервалы 1×, 2× и 4× равны 460, 230 и 110 мс. «Шаг» останавливает пуск. «Сначала» сохраняет переключатели, скорость и пуск. Режим действует со следующего шага. Нечисловое и пустое зерно игнорируются; конечное число усекается и ограничивается 1–999. Щелчок внутри поля включает фиксацию. Показ истины и гипотез не меняет эпизод.

Расчёт bench начинается один раз в отдельном потоке. До получения результата видна надпись «Идёт расчёт…», при ошибке запуска потока, разрыве канала или панике – «Не удалось рассчитать бенчмарк.». Состояние и подписи находятся в модулях без импорта egui; графика читает снимок эпизода и передаёт только управляющие действия.

### Проверки окна

`cargo test -p viewer` запускает проверки действий, таймера, подписей, координат, цвета и интерфейса через доступные имена элементов. Полные снимки сериализуются так же, как в трассах R1. Проверяются все действия и последовательность из 60 смешанных действий, 48 сочетаний строки состояния и ввод зерна. Только один тест рассчитывает настоящий bench для проверки каждой строки итоговой таблицы; остальные используют ожидающий или ошибочный протокол.

`VIEWER_SCREENSHOTS=/tmp/coherence-viewer cargo test -p viewer completed_protocol -- --nocapture` сохраняет двенадцать PNG размером 1440 × 1000 и 480 × 1000. Каталог должен находиться вне репозитория. Для рендера тесту нужен доступ к графическому адаптеру; обычным проверкам интерфейса он не нужен. Снимки показывают начальное состояние, 30 шагов непрерывности с истиной и без неё, 40 шагов конфликта на зерне 2, фиксацию в (30, 70) и готовый протокол. Для сцены и протокола область просмотра прокручивается к соответствующему разделу.

Общие проверки – `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`. `node tools/check-print.mjs` дополнительно сверяет русское форматирование разницы в процентных пунктах с Node на случайных и граничных значениях, включая знак округлённого нуля. `node tools/check-commands.mjs` проверяет прежние семь команд.
