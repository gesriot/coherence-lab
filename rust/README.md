# Стенд на Rust

Команды выполняются из каталога `rust/`. Эталон – Node 26.3.1, V8 14.6.202.34-node.20, arm64 macOS, сборка Homebrew. Для сборки нужен Rust edition 2024 и компилятор C++20. Node нужен для сравнений с TypeScript.

## Числа

`node tools/check-math.mjs` собирает проверяющую программу и передаёт ей входы и ожидаемые binary64 непосредственно из Node. Для каждой операции берутся 100 000 значений на рабочих диапазонах, ещё 100 000 на смешанных диапазонах и 712 граничных комбинаций, в том числе числа NaN с разными знаками, типами и полезной нагрузкой. Сравнение – по всем 64 битам, включая знак нуля и биты NaN. Векторы не записываются в репозиторий.

| Операция | Реализация |
| :-- | :-- |
| sin, cos | В установленной libnode экспортированы `v8::base::ieee754::sin/cos`. Флага `--use-libm-trig-functions` у этой сборки нет. Используются ядра fdlibm, включая редукцию больших аргументов по π/2. |
| exp, log, log1p, tanh, atan2 | Функции из того же исходника V8, включая внутренние expm1 и atan, особый случай exp(1) и signaling NaN при выходе логарифма за область определения. |
| hypot | Алгоритм math.tq: максимум модулей, нормирование, умножение на масштаб после sqrt. Для трёх и более аргументов учитывается компенсация потери точности. Бесконечность имеет приоритет над NaN. |
| abs, sqrt, ceil, floor | Операции binary64, как у Float64Abs, Float64Sqrt, Float64Ceil и Float64Floor. Константы PI и SQRT2 имеют ближайшее представимое значение. |
| round, sign, min, max | Ветви ECMAScript: половины округляются к большему, знак нуля сохраняется, Для NaN в min/max воспроизводится порядок обработки аргументов встроенной функцией V8 на arm64. При двух signaling NaN оптимизированный JIT-вызов может выбрать другую полезную нагрузку. В стенде этот случай не возникает. |
| ToInt32, ToUint32, imul | Выделение младших 32 бит усечённой мантиссы и умножение по модулю 2³². hashUnit и hueNoise повторяют math.ts, с беззнаковыми сдвигами. |

Исходники эталона: [ieee754.cc](https://github.com/nodejs/node/blob/v26.3.1/deps/v8/src/base/ieee754.cc), [выбор функций](https://github.com/nodejs/node/blob/v26.3.1/deps/v8/src/codegen/external-reference.cc), [math.tq](https://github.com/nodejs/node/blob/v26.3.1/deps/v8/src/builtins/math.tq). Выбранные ядра собраны статически в jscompat, лицензии лежат рядом с Cargo.toml крейта. Исходные скобки и промежуточные присваивания сохранены. В дизассемблере установленной libnode внутри полинома sin видна серия инструкций fmadd. Например, при −0,6962983277626336 отдельное округление умножения и сложения меняет последний бит. Поэтому только для этих ядер используется режим Clang `-ffp-contract=on` без fast-math. В формулах модели обычные операции Rust округляются отдельно. Другая архитектура или компилятор требуют повторной битовой сверки.

## Текст команд

`node tools/check-print.mjs` сравнивает три формы чисел с Node, а также многострочные таблицы и строки журнала. `number` использует кратчайшую ECMAScript-запись Ryū. Для `to_fixed` двоичная мантисса точно масштабируется степенями 5 и 2 в BigUint, включая округление половин и предел в 100 знаков. Таблица принимает заголовки и упорядоченные строки чисел и текста. Поддержаны формы console.log, используемые стендом, без форматных подстановок. Ширина повторяет ASCII-префикс, удаление VT-последовательностей, нормализацию NFC и ширины символов ICU сборки Node. Диапазоны свойств восстанавливаются командой `node tools/width-data.mjs`.

## Эпизоды версии A

`cargo test -p lab` проверяет четыре SHA-256 цепочек JSON с координатами взгляда, треками и энергией, а также свойства сценариев и политик. Агент получает только сенсорный кадр и управляющие параметры. Оценщик сопоставляет треки с объектами мира после шага.

`node tools/check-traces.mjs` записывает пары файлов NDJSON во временный каталог и проверяет все поля полного снимка, включая начальный кадр. Можно передать путь для сохранения трасс. В имени файла указаны сценарий, политика, зерно и режим. При расхождении печатаются номер кадра, путь к полю и оба значения. Сравнение охватывает все условия bench на зёрнах 1, 2 и 17, включая повтор с 15-го шага, а также эпизод vanish с начальной обучаемой моделью.

## Стенд bench

`cargo run --release -p cli -- bench` последовательно выполняет шесть политик на зёрнах 1–200. Вывод включает заголовок эталонной npm-команды. `node tools/check-bench.mjs` предварительно собирает release, запускает обе команды на этой машине и сравнивает stdout как массивы байтов. При совпадении печатаются размер, SHA-256 и время каждой команды.
